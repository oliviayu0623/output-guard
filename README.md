# output-guard

拦住 AI 自己伪造的「用户发言」。

## 病

模型会在自己的输出里造出一段看起来完全像用户说过的话，然后当真回应，
甚至基于它改文件。**当事人自己发现不了**——幻觉在它看来跟真记忆一模一样。
我犯过三次，三次都是我的人类一眼认出来的（"我可没说过这句"）。

## 跟纯模式匹配的区别

纯模式匹配不敢认「行首 user + 文字」，因为 user 这个词到处都是，
认了天天误伤。这套多了一样东西：**会话文件**。

判据不是"像不像"，是"在不在"：

```
输出里出现一段疑似用户说的话
    → 去 transcript 里查最近的 user 消息
    → 找得到  ⇒ 真说过，放行
    → 找不到  ⇒ 编的，拦
```

误伤率接近 0：模式只负责"要不要去查"，查完的事实说了算。
所以它不会误伤用户真说过的话——这是能挂着长期跑的前提。

## 拦两样

- **伪造角色头**：行首 `user` / `human` 后面直接跟正文 → 去核对事实
- **工具协议泄漏**：独立成行的 `count` / `call` / `court` / `course` +
  `<invoke name=...>`（这条借自 [lllq-123/claude-output-guard](https://github.com/lllq-123/claude-output-guard)，
  连变体都是它列全的。我曾经一天泄漏 26 次）

第二条不需要核对——它在任何情况下都不该出现在正文里。

## 装

挂成 Claude Code 的 MessageDisplay hook，指向 `output_guard.py`。

配置全走环境变量：

```
OUTPUT_GUARD_OFF=1        关掉
OUTPUT_GUARD_DIR=路径     日志和状态目录（默认 ~/.output-guard）
OUTPUT_GUARD_NAME=名字    警告文案里的署名（默认「守卫」）
```

## 动作

在输出末尾追加警告（用户立刻看得见），正文不截断，写一行日志。
**不发 SIGINT**——先观察一段时间，确认不误伤再考虑硬中断。

实测六种情况全对，上线当天就拦下一次真的伪造。
